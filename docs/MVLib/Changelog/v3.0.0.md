# MVLib v3.0.0 Changelog

Source range: `919e915b4465711dcc3d94108c0d7ae88e165fd8..`

## Breaking Changes

- `MVLIB_VERSION` was updated from `2.0.0` to `3.0.0`.
- `Logger::setLoggingFolder(...)` was replaced by `Logger::setLoggingLocation(...)`, which accepts either a folder or explicit file path plus `MissingFolderPolicy` and `ExistingFilePolicy` options.
- `Logger::setLoggerMinLevel(...)` was renamed to `Logger::setMinLogLevel(...)`.
- `Logger::pause(bool byForce = false)` was simplified to `Logger::pause()`. The public force-suspend option was removed.
- `Logger::watch(...)` now takes an explicit `WatchMode` (`WatchMode::onInterval` or `WatchMode::onChange`) instead of the previous boolean watch mode argument.
- `Logger::watch(...)` no longer accepts a printf-style watch format specifier. Floating-point watch values now render with two decimal places.
- `Logger::addWaypoint(...)` now rejects waypoint names longer than 24 characters at compile time for string literals. Live MotionView roster display is limited to 23 visible characters because the telemetry name field is null-terminated.
- `WaypointOffset::timedOut` changed from `std::optional<bool>` to `bool`.
- Public telemetry internals were moved out of `mvlib/telemetry.hpp` and into `mvlib/private/telemetry.hpp`. User code should include `mvlib/api.hpp`, `mvlib/core.hpp`, `mvlib/types.hpp`, `mvlib/watches.hpp`, and `mvlib/waypoint.hpp` instead of using telemetry internals directly.

## New Features

- Added `mvlib/types.hpp` for shared public types such as `LogLevel`, `Pose`, `LoggerTimings`, and `LoggerConfig`.
- Added `mvlib/watches.hpp` with `WatchMode`, `LevelOverride`, `WatchHandle`, and watch predicate helpers.
- Added `WatchHandle` controls for checking validity/activity, enabling or disabling a watch, reading and updating intervals, changing watch mode, evaluating a watch immediately, and resyncing watch roster metadata.
- Added separate waypoint handle implementation with `getParams()`, `getLabel()`, `reached()`, `timedOut()`, `active()`, and `resyncRoster()` behavior backed by internal waypoint lookup helpers.
- Added SD logging to explicit filenames as well as folders, including overwrite, disable, and automatic timestamp fallback behavior when a file already exists.
- Added POSIX-style SD path normalization for logging destinations while still talking to the VEX filesystem with the required path format internally.
- Added a buffered telemetry transmit task with queueing, batching, retry handling, and non-blocking packet drops when the queue is full.
- Added structured text-watch packets alongside numeric watch packets so non-numeric watch values can still flow through the binary telemetry channel.
- Added `MVLIB_USE_SIMPLES` aliases for `WatchMode`, `MissingFolderPolicy`, and `ExistingFilePolicy`.

## Improvements

- Refactored `core.hpp` by moving public types, watch APIs, private utility helpers, and RAII mutex handling into focused headers.
- Reworked watch printing so user callbacks are evaluated outside the main logger mutex, reducing recursive mutex/deadlock risk.
- Reworked pose getter access so pose callbacks are protected by their own mutex and no longer run while the main logger mutex is held.
- Reworked waypoint offset, reached, timeout, and roster lookup paths around internal find helpers.
- Split the fixed logger update cadence from pose telemetry output cadence. Watches and waypoints now run on the internal 40 ms loop, while terminal/SD pose telemetry is still capped by the configured polling intervals.
- Moved pose telemetry printing into its own `printTelemetry()` path and separated telemetry throttling from stdout buffer flush timing.
- Improved default drivetrain and battery watchdog watches to use `WatchMode::onChange`, clearer threshold predicates, and less noisy system logging.
- Standardized floating-point watch display, SD logging, and on-change comparison around two-decimal rendering.
- Improved terminal telemetry filtering by using the telemetry backend as the shared minimum-log-level source of truth for terminal and SD output.
- Improved SD log filename generation with second-level timestamps, randomized suffixes, root-folder handling, and better RTC fallback naming.
- Improved logger startup diagnostics, SD card initialization messages, and system log wording.
- Updated optional odometry adapters for LemLib, Okapi, EZ-Template, and custom odometry to include the new public type headers and refreshed examples.
- Updated Doxygen formatting and comments across the public MVLib headers.
- Added `Logger::setBuildDate` for automatic timestamped SD log filenames.

## Removals

- Removed `mvlib/telemetry.hpp` from the public API surface.
- Removed the old `MVLib/src/mvlib/telemetry.cpp` location in favor of `MVLib/src/mvlib/sinks/telemetry.cpp`.
- Removed the old `MVLib/src/mvlib/waypointHandle.cpp` location in favor of `MVLib/src/mvlib/handles/waypointHandle.cpp`.
- Removed the old internal `unique_lock`, formatting, and unreachable helpers from `core.hpp`; these now live in private helper headers.
- Removed legacy waypoint helper methods from the public logger surface that are now represented by `WaypointHandle` methods and internal lookup helpers.

## Bug Fixes

- Fixed a telemetry theta encoding rounding bug by encoding the full `[0, 360)` range into the `uint16_t` ring with `65536 / 360` scaling.
- Fixed recursive mutex/deadlock issues involving watch callbacks and pose getter callbacks.
- Fixed watch change detection so on-change watches honor both value changes and debounce intervals.
- Fixed watch SD output for booleans so compact terminal values are expanded to `true`/`false` in SD logs.
- Fixed waypoint timeout lifecycle tracking so an active waypoint that expires is marked timed out and deactivated before any later reached handling, while a non-retriggerable waypoint reached before timeout remains inactive and does not later become timed out.
- Fixed waypoint reached lifecycle reporting so `WaypointHandle::reached()` and `WaypointOffset::reached` report the stored "has ever reached" state, including retriggerable waypoints that later leave tolerance.
- Fixed `WaypointHandle::timedOut()`, `Logger::getWaypointOffset(...)`, terminal waypoint packets, and SD waypoint status output to read the stored waypoint lifecycle state instead of recomputing timeout status from the current wall-clock time.
- Fixed `setLogToSD(false)` and SD initialization paths so SD logging is locked or disabled more predictably after startup failures.
- Fixed default watch threshold comparisons around drivetrain temperature, battery temperature, and battery voltage edge cases.
- Fixed `setMinLogLevel(...)` so `LogLevel::OVERRIDE` cannot become the global filter level.
- Fixed custom odometry compile-time diagnostics after moving common helper templates out of `core.hpp`.
