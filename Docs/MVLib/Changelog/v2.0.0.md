# MVLib v2.0.0 Changelog

Source range: `6c69d0fbaf1be8af2c85a1409b3b4c2fc8433d24..1f32cd9ded9067b9d775bb6c939f9307ab92b618`

## Breaking Changes

- MVLib terminal telemetry moved from the old plain-text MotionView stream to a binary packet protocol for poses, watches, waypoints, roster data, and logs. Older MotionView builds will not fully understand the new live stream format.
- `LoggerTimings` field names were renamed from snake_case to camelCase: `sd_buffer_flush_interval` -> `sdBufferFlushInterval`, `sd_polling_rate` -> `sdPollingRate`, and `terminal_polling_rate` -> `terminalPollingRate`.
- `LoggerTimings` now also owns `stdoutBufferFlushInterval` and `rosterSyncAllInterval`, so timing configuration is no longer just the previous 3-field layout.
- `WatchId` and `WPId` were narrowed from `uint64_t` to `uint16_t`.
- `WaypointParams::logOffsetEveryMs` was removed. Waypoints now emit creation and state-change events instead of periodic terminal offset lines.
- After `Logger::getInstance()` is created, MVLib disables the standard PROS user-serial framing path used by ordinary terminal printing. `printf`/raw stdout is no longer safe for MVLib live telemetry; use `logger.debug/info/warn/error/fatal(...)`.
- SD log routing was introduced with `setLoggingFolder(...)`. In newer MVLib releases this API has been replaced by `setLoggingLocation(...)`.

## New Features

- Added a dedicated telemetry engine in `telemetry.hpp/.cpp` with compact binary packets for high-speed live MotionView updates.
- Added roster sync packets so late-joining MotionView sessions can recover watch and waypoint names reliably.
- Added binary numeric watch packets plus structured text-watch packets, including elevated/tripped watch state handling.
- Added waypoint creation packets and roster re-sync helpers, including `WaypointHandle::resyncRoster()`.
- Added SD log routing so teams can direct SD logs into a chosen folder instead of always using the SD root.
- Added `stdoutBufferFlushInterval` control for terminal flushing.
- Added `rosterSyncAllInterval` to periodically refresh watch/waypoint metadata on the wire.
- `mvlib/api.hpp` now exposes the telemetry interface directly.

## Removals

- Removed the old terminal-side plain-text waypoint offset stream driven by `logOffsetEveryMs`.
- Removed the previous `standardLog.cpp` path in favor of the new centralized logging/telemetry backend in `logs.cpp`.
- Replaced the packaged release artifact `libmvlib@1.1.0.zip` with `libmvlib@2.0.0.zip`.

## Bug Fixes

- Fixed Okapi odometry setup so the selected distance units are captured correctly by the pose getter.
- Fixed waypoint reach evaluation and state transitions, including timeout/retrigger behavior.
- Fixed SD log filename generation so custom folders are respected and RTC fallback naming is more robust.
- Fixed default drivetrain and battery watchdog watches to debounce repeated fault spam instead of re-logging constantly.
- Fixed `setLoggerMinLevel(...)` so the new telemetry backend actually enforces the selected minimum level.
- Fixed watch and waypoint name recovery by adding internal lookup helpers used by roster resync.
